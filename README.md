# ITL Server Scripts

Централизованная библиотека административных скриптов ITL для настройки
безопасности, диагностики, мониторинга, резервного копирования и обслуживания
Debian/Ubuntu. Каждый инструмент скачивается и запускается отдельно.
Сторонние пакеты Python, агент и постоянно работающая служба не требуются.

## Поддерживаемые системы

Первый инструмент рассчитан на Debian 12/13 и Ubuntu 22.04/24.04 с Python 3.9+
и стандартным пакетным OpenSSH `/usr/sbin/sshd` под управлением systemd.
Это целевые платформы, а не заявление о выполненных проверках на каждой ОС.
Фактическая проверка описана в [docs/VALIDATION.md](docs/VALIDATION.md).

Не поддерживаются альтернативные конфиги через `sshd -f`, переопределения
через `-o`, несколько отдельных служб SSH и нестандартные исполняемые файлы.
При нераспознанном запуске скрипт прекращает работу до изменения конфигов.

## Получение через curl

Для рабочего сервера используйте опубликованную фиксированную версию.
Команды ниже для `v0.1.0` работают после публикации этого релиза.
Сначала скачайте файл от обычного пользователя в отдельный каталог:

```bash
mkdir -p "$HOME/itl-server-scripts-v0.1.0"
cd "$HOME/itl-server-scripts-v0.1.0"
curl --fail --show-error --location --proto '=https' --tlsv1.2 \
  --output disable_root_ssh_password.py \
  https://raw.githubusercontent.com/inzheev/itl-server-scripts/v0.1.0/ssh/disable_root_ssh_password.py
python3 -m py_compile disable_root_ssh_password.py
less disable_root_ssh_password.py
```

Скачивание и запуск выполняются отдельными командами. При ошибке curl
не запускайте оставшийся от предыдущей загрузки файл. Релизные теги не
переносятся; для более строгой фиксации используйте полный SHA коммита
вместо `v0.1.0` в raw-ссылке. В заметках релиза публикуется SHA-256 скрипта.

Получить текущую разрабатываемую версию можно отдельно:

```bash
mkdir -p "$HOME/itl-server-scripts-main"
cd "$HOME/itl-server-scripts-main"
curl --fail --show-error --location --proto '=https' --tlsv1.2 \
  --output disable_root_ssh_password.py \
  https://raw.githubusercontent.com/inzheev/itl-server-scripts/main/ssh/disable_root_ssh_password.py
less disable_root_ssh_password.py
```

`main` изменяется со временем. Обновление через curl — повторное скачивание
явно выбранной версии с просмотром изменений и повторной проверкой.

## Получение через Git и обновление

```bash
git clone https://github.com/inzheev/itl-server-scripts.git
cd itl-server-scripts
git switch main
git pull --ff-only
```

Для выбора проверенного релиза после клонирования:

```bash
git fetch --tags
git switch --detach v0.1.0
python3 -m py_compile ssh/disable_root_ssh_password.py
```

Для обновления рабочего сервера получите теги, прочитайте заметки следующего
релиза и переключитесь на его конкретный тег. `git pull --ff-only` обновляет
ветку `main`; в состоянии detached HEAD его использовать не нужно.
Не перезаписывайте локальные изменения автоматически.

## SSH: проверка и применение

Перед запуском нужен уже проверенный вход root по ключу в **новой отдельной
SSH-сессии**, либо другой рабочий административный доступ. Сохраните текущую
сессию и доступ к консоли провайдера. Скрипт не устанавливает ключи и не
проверяет доступность SSH по сети.

В каталоге со скачанным одиночным файлом:

```bash
# Только аудит конфигурации; найденные разрешения дают код возврата 2.
sudo python3 ./disable_root_ssh_password.py --check

# Применение через reload, если обнаружены разрешающие директивы.
sudo python3 ./disable_root_ssh_password.py

# Альтернатива reload: restart, только когда это явно необходимо.
sudo python3 ./disable_root_ssh_password.py --restart

# Повторная проверка конфигурации.
sudo python3 ./disable_root_ssh_password.py --check
```

При работе из клона используйте путь `ssh/disable_root_ssh_password.py` вместо
`./disable_root_ssh_password.py`. `sudo` нужен только при запуске не из root;
если sudo отсутствует, выполняйте команды из имеющейся root-сессии без него.
Параметры `--check` и `--restart` взаимоисключающие.

Скрипт проверяет службу и командную строку процесса, запускает `sshd -t`,
обходит достижимые `Include`, включая расположенные внутри `Match`.
Все явные `PermitRootLogin yes`, в том числе перекрытые другими директивами,
заменяются на `prohibit-password`. Поэтому код 2 означает наличие разрешающих
строк, а не доказанный успешный вход по паролю. Уже заданные `no`,
`forced-commands-only`, `without-password` и `prohibit-password` сохраняются.
Ключи и `PubkeyAuthentication` не меняются, доступ, ранее запрещённый политикой,
не открывается. Семантика соответствует [документации OpenSSH](https://man.openbsd.org/sshd_config#PermitRootLogin).

Перед изменениями создаются резервные копии в
`/var/backups/ssh-root-password-<UTC>-<суффикс>/` с исходным деревом абсолютных
путей. Сохраняются владелец, группа и режим доступа; запись конфигов атомарная.
После редактирования выполняются `sshd -t`, проверка политики, reload/restart,
проверка состояния active и повторная проверка политики. Это проверка файлов
и службы, а не пробный сетевой вход. После применения **самостоятельно откройте
новую сессию по ключу**, прежде чем закрывать старую.

Если менять нечего, копии не создаются и reload/restart не выполняется даже
при `--restart`. Состояние уже загруженной конфигурации службы в этом случае
не доказывается. `--check` не редактирует конфиги, но использует служебный файл
блокировки в `/run/lock`, чтобы не пересечься с другим экземпляром.

### MFA и ограничения

`prohibit-password` запрещает root также keyboard-interactive, включая некоторые
варианты MFA. Скрипт консервативно отказывается от изменений, если хотя бы одна
достижимая `AuthenticationMethods` требует пароль/keyboard-interactive во всех
альтернативах. Отказ возможен даже для блока `Match`, фактически относящегося
только к другому пользователю; это требует ручного анализа. Дополнительно
проверяются эффективные политики root для loopback IPv4/IPv6 и, при наличии,
адресов текущей SSH-сессии из `SSH_CONNECTION`.

Полного перебора всех адресов/групп/имён хостов нет. Необычные шаблоны Include
с `[]`, `~` и экранированием, циклы, слишком глубокие включения, небезопасные
права и изменяемые файлы с несколькими жёсткими ссылками приводят к отказу.
Не меняйте конфигурацию SSH параллельно другим инструментом. Пароль учётной
записи, PAM, firewall, правила Allow/Deny, сроки действия ключей и доступность
сервера остаются вне области проверки.

| Код возврата | Значение |
| --- | --- |
| `0` | Успех: безопасная политика в файлах либо изменения применены |
| `2` | Только `--check`: найдены явные разрешающие директивы |
| `1` | Ошибка или защитный отказ; внимательно прочитайте результат отката |

### Ошибка и восстановление

При ошибке после записи скрипт пытается восстановить изменённые файлы из
копий, проверяет синтаксис и при необходимости повторно применяет исходную
конфигурацию. Это попытка восстановления, не гарантия при потере питания,
`SIGKILL`, ошибках диска или внешних изменениях. Сообщение `[CRITICAL]` означает
неполный откат; копии остаются на сервере. Через консоль администратора
сравните копии с текущими файлами, восстановите только необходимые файлы,
проверьте `sshd -t`, затем примените конфигурацию штатной службы SSH.
Откат возвращает прежнюю политику, которая могла разрешать пароль root.

## Разработка и проверки

Файлы инструментов: `snake_case.py` или `snake_case.sh` в профильном каталоге.
В документации каждого инструмента указываются назначение, ОС, зависимости,
привилегии, параметры, коды возврата, изменения и порядок восстановления.
Дополнительные административные инструменты сейчас не создаются.

Разработка и CI: Python **3.12.12** (`.python-version`), стандартная библиотека.
Рабочие серверы используют системный Python 3.9+; смена системного Python не нужна.
Проверки из корня клона без root и без доступа к серверам:

```bash
python3 tools/check_repository.py
python3 -m unittest discover -s tests -v
```

GitHub Actions запускает те же команды на push и pull request, с минимальными
правами `contents: read`; официальные actions зафиксированы полными SHA.
Проверяются синтаксис Python, `bash -n` для `.sh`/`.bash` и shell shebang,
типовые секреты и внутренние IPv4-адреса в отслеживаемых файлах. Проверка
эвристическая: не заменяет ручной просмотр, не обнаруживает все виды секретов
и не проверяет историю Git. Значения возможных секретов в журнал не выводятся.
Тесты работают с временными конфигами, имитируют root-владельца и команды
службы, не изменяют системный SSH и не требуют root.

## Версии

Используется [Semantic Versioning](https://semver.org/lang/ru/): `MAJOR.MINOR.PATCH`,
теги `vX.Y.Z`. До `1.0.0` совместимость оценивается по заметкам каждого релиза.
Первый запланированный релиз — `v0.1.0`; опубликованные версии доступны в
[Releases](https://github.com/inzheev/itl-server-scripts/releases).
Порядок публикации и проверки описан в [docs/RELEASING.md](docs/RELEASING.md).
Изменения не скачиваются и не применяются к серверам автоматически.
