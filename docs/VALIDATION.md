# Проверка первого инструмента

Дата: 9 ноября 2026 года. Основа — исходный `disable_root_ssh_password.py`,
предоставленный ранее пользователем; скрипт не заменён новой реализацией.

## Изменения после ревью

- Повторный запуск без разрешающих строк завершает проверку без reload/restart
  и без создания резервных копий, включая запуск с `--restart`.
- Перед изменениями проверяются все достижимые `AuthenticationMethods`:
  обязательный пароль/keyboard-interactive вызывает защитный отказ даже в
  блоке Match вне выборки адресов текущего подключения. Это консервативная
  проверка с возможными отказами для блоков, не относящихся к root.
- Сохранены исходные обход Include/Match, резервирование, атомарная запись,
  проверка конфигурации, проверка службы и попытка отката.

## Выполнено локально

Среда: macOS arm64, Python 3.9.6, OpenSSH 10.3p1. Выполнены:

```bash
python3 tools/check_repository.py
python3 -m unittest discover -s tests -v
```

Результат: синтаксис Python корректен, эвристическая проверка отслеживаемых
файлов не выявила секретов; 22 теста прошли. Bash-файлов пока нет.

Проверены рекурсивные Include и Match, комментарии, CRLF, сохранение более
строгих запретов, идемпотентность, циклы, права доступа, жёсткие ссылки,
неподдерживаемый синтаксис, MFA, режим аудита, резервная копия,
успешное применение, ошибка проверки синтаксиса, ошибка reload, восстановление,
конкурентное изменение, отказ небезопасного restart, таймаут команды и запуск
без root. Владелец root и операции службы имитируются только внутри тестов.

Отдельный тест создаёт временный host key и временные конфиги, затем вызывает
настоящий `/usr/sbin/sshd -t` и `sshd -T -C` до и после преобразования.
Демон не запускается, сетевые порты не открываются. Если OpenSSH server или
ssh-keygen отсутствуют, только этот тест явно пропускается.

## GitHub Actions

Workflow использует Python 3.12.12 на `ubuntu-24.04`. Актуальные результаты
проверки конкретного коммита, включая возможные пропуски тестов, доступны в
[Actions](https://github.com/inzheev/itl-server-scripts/actions/workflows/checks.yml).
Локальный успех не означает успешный запуск workflow; релиз выпускается
после отдельного подтверждения успеха CI для публикуемого коммита.

## Границы проверки

Реальные службы Debian/Ubuntu не изменялись, системные конфиги тестовой машины
не редактировались. Изолированные тесты не доказывают успешный вход по сети,
совместимость с каждым пакетом OpenSSH, PAM, socket activation, политиками
SELinux/AppArmor и всеми настройками systemd на целевых серверах.
Перед применением на рабочих серверах нужен пилот на одноразовой VM с
консолью и проверкой новой SSH-сессии по ключу. Полный перебор всех Match
контекстов и гарантия отката после аварийного завершения не заявляются.
