# Выпуск версии

1. Просмотреть изменения и обновить README, тесты и фактические результаты
   проверки. Не включать в коммит конфиги реальных серверов, копии и секреты.
2. Выполнить обе команды проверки из README без root. Изменения поведения SSH
   дополнительно проверить на одноразовой Debian/Ubuntu VM с консольным доступом.
3. Опубликовать коммит в `main`, дождаться успешного workflow `Repository checks`
   именно для его полного SHA. При ошибке исправить причину; не отключать проверки.
4. Выбрать следующую SemVer-версию. Создать тег на проверенном коммите и релиз
   с тем же именем, например `v0.1.0`. Не переносить опубликованные теги.
5. В заметках описать изменения, поддерживаемые системы, ограничения, фактически
   выполненные проверки и SHA-256 файла `ssh/disable_root_ssh_password.py`.
6. Убедиться, что публичные ссылки репозитория, файла с тегом и релиза доступны.
   Скачать файл по ссылке с тегом и сравнить его SHA-256 с проверенным локальным.

Скачивание фиксированной версии:

```bash
curl --fail --show-error --location --proto '=https' --tlsv1.2 \
  --output disable_root_ssh_password.py \
  https://raw.githubusercontent.com/inzheev/itl-server-scripts/v0.1.0/ssh/disable_root_ssh_password.py
```

Публикация версии не означает её применение к рабочим серверам.
